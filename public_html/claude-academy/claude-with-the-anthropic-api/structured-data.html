Structured data

Dữ liệu có cấu trúc

The Problem

Vấn đề

When you need Claude to generate structured data like JSON, Python code, or bulleted lists, you'll often run into a common problem: Claude wants to be helpful and add explanatory text around your content. While this is usually great, sometimes you need just the raw data with nothing else.

Consider building a web app that generates AWS EventBridge rules. Users enter a description, click generate, and expect to see clean JSON they can immediately copy and use. If Claude returns the JSON wrapped in markdown code blocks with explanatory text, users can't simply copy the entire response — they have to manually select just the JSON portion.

By default, when you ask Claude to generate JSON, you might get something like this:

```json
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["running"]
  }
}
```

This rule captures EC2 instance state changes when instances start running.

The JSON is correct, but it's wrapped in markdown formatting and includes explanatory text. For a web app where users need to copy the raw JSON, this creates friction in the user experience.

Khi bạn cần Claude tạo dữ liệu có cấu trúc như JSON, code Python hoặc danh sách có dấu đầu dòng, bạn thường gặp phải một vấn đề phổ biến: Claude muốn hữu ích và thêm văn bản giải thích xung quanh nội dung của bạn. Mặc dù điều này thường tốt, đôi khi bạn chỉ cần dữ liệu thô không có gì khác.

Hãy xem xét việc xây dựng một web app tạo các AWS EventBridge rule. Người dùng nhập mô tả, nhấp tạo và mong đợi thấy JSON sạch mà họ có thể sao chép và sử dụng ngay. Nếu Claude trả về JSON được bọc trong các code block markdown với văn bản giải thích, người dùng không thể đơn giản sao chép toàn bộ phản hồi — họ phải chọn thủ công chỉ phần JSON.

Theo mặc định, khi bạn yêu cầu Claude tạo JSON, bạn có thể nhận được như sau:

```json
{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["running"]
  }
}
```

This rule captures EC2 instance state changes when instances start running.

JSON là đúng, nhưng nó được bọc trong định dạng markdown và bao gồm văn bản giải thích. Với web app nơi người dùng cần sao chép JSON thô, điều này tạo ra ma sát trong trải nghiệm người dùng.

The Solution: Prefilling and Stop Sequences

Giải pháp: Prefilling và Stop Sequences

You can combine assistant message prefilling with stop sequences to get exactly the content you want:

messages = []

add_user_message(messages, "Generate a very short event bridge rule as json")
add_assistant_message(messages, "```json")

text = chat(messages, stop_sequences=["```"])

This technique works by:

  1. The user message tells Claude what to generate
  2. The prefilled assistant message makes Claude think it already started a markdown code block
  3. Claude continues by writing just the JSON content
  4. When Claude tries to close the code block, the stop sequence immediately ends generation

The result is clean JSON with no extra formatting:

{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["running"]
  }
}

Bạn có thể kết hợp prefilling message trợ lý với stop sequence để nhận chính xác nội dung bạn muốn:

messages = []

add_user_message(messages, "Generate a very short event bridge rule as json")
add_assistant_message(messages, "```json")

text = chat(messages, stop_sequences=["```"])

Kỹ thuật này hoạt động bằng cách:

  1. User message cho Claude biết phải tạo gì
  2. Message trợ lý được điền trước khiến Claude nghĩ rằng nó đã bắt đầu một markdown code block
  3. Claude tiếp tục bằng cách chỉ viết nội dung JSON
  4. Khi Claude cố gắng đóng code block, stop sequence ngay lập tức kết thúc quá trình tạo

Kết quả là JSON sạch không có định dạng thêm:

{
  "source": ["aws.ec2"],
  "detail-type": ["EC2 Instance State-change Notification"],
  "detail": {
    "state": ["running"]
  }
}

Processing and Beyond

Xử lý và mở rộng

You might notice some extra newline characters in the response. These are easy to handle:

import json

# Clean up and parse the JSON
clean_json = json.loads(text.strip())

This technique isn't limited to JSON generation. Use it anytime you need structured data without commentary:

  • Python code snippets
  • Bulleted lists
  • CSV data
  • Any formatted content where you want just the content, not explanations

The key is identifying what Claude naturally wants to wrap your content in, then using that as your prefill and stop sequence. This approach gives you precise control over Claude's output format, making it much easier to integrate AI-generated content into applications where clean, structured data is essential.

Bạn có thể nhận thấy một số ký tự xuống dòng thêm trong phản hồi. Chúng dễ xử lý:

import json

# Làm sạch và phân tích JSON
clean_json = json.loads(text.strip())

Kỹ thuật này không giới hạn ở việc tạo JSON. Sử dụng nó bất cứ khi nào bạn cần dữ liệu có cấu trúc mà không có bình luận:

  • Các đoạn code Python
  • Danh sách có dấu đầu dòng
  • Dữ liệu CSV
  • Bất kỳ nội dung có định dạng nào mà bạn chỉ muốn nội dung, không phải giải thích

Điều quan trọng là xác định những gì Claude tự nhiên muốn bọc nội dung của bạn, sau đó sử dụng điều đó làm prefill và stop sequence của bạn. Cách tiếp cận này cho bạn kiểm soát chính xác định dạng đầu ra của Claude, giúp dễ dàng tích hợp nội dung do AI tạo ra vào các ứng dụng nơi dữ liệu sạch, có cấu trúc là thiết yếu.

Why Structured Output?

By default, Claude returns free-form text. This is great for conversations and summaries, but many real-world applications need Claude's output to feed directly into code — a database insert, an API call, a UI component.

For these use cases, you need structured output: a predictable, machine-readable format (typically JSON) that your application can parse and use without brittle string manipulation.

Common scenarios where structured output is essential:

  • Extracting entities from a document (names, dates, amounts)
  • Classifying content and returning a category + confidence score
  • Populating a form or database record from unstructured input
  • Returning multiple fields in one API call (e.g. summary, sentiment, tags)

Prompting for JSON Output

The simplest approach is to instruct Claude to respond with JSON in your system prompt, and specify the exact schema you expect:

client.messages.create(
    model="claude-opus-4-5",
    max_tokens=1024,
    system="""You are a data extraction assistant.
Always respond with a JSON object containing exactly these fields:
- name (string)
- date (string, ISO 8601 format)
- amount (number)
Respond with JSON only. No explanation.""",
    messages=[
        {"role": "user", "content": "Invoice from Acme Corp on March 5 2024 for $1,250."}
    ]
)

Tips for reliable JSON output:

  • Say "Respond with JSON only" — this discourages preamble text
  • Define the schema explicitly, including field names and types
  • Use "No explanation" or "No markdown" to suppress code fences

Parsing and Validation

Once Claude returns JSON, parse and validate it in your application. A robust pattern using Pydantic:

import json
from pydantic import BaseModel

class Invoice(BaseModel):
    name: str
    date: str
    amount: float

response_text = message.content[0].text

try:
    data = json.loads(response_text)
    invoice = Invoice(**data)
    print(invoice.name, invoice.amount)
except (json.JSONDecodeError, ValueError) as e:
    print(f"Parse error: {e}")
    # Retry or handle gracefully

Pydantic automatically validates field types and raises a clear error if Claude returns unexpected data.

Tại sao cần Structured Output?

Theo mặc định, Claude trả về văn bản tự do. Điều này tốt cho hội thoại và tóm tắt, nhưng nhiều ứng dụng thực tế cần đầu ra của Claude đưa trực tiếp vào code — một lệnh insert database, một API call, một UI component.

Với những trường hợp này, bạn cần structured output: một định dạng có thể dự đoán, đọc được bởi máy (thường là JSON) mà ứng dụng của bạn có thể phân tích và sử dụng mà không cần thao tác chuỗi dễ gãy.

Các tình huống phổ biến mà structured output là thiết yếu:

  • Trích xuất thực thể từ tài liệu (tên, ngày, số tiền)
  • Phân loại nội dung và trả về danh mục + điểm tin cậy
  • Điền vào form hoặc bản ghi database từ đầu vào phi cấu trúc
  • Trả về nhiều trường trong một API call (ví dụ: summary, sentiment, tags)

Prompt để nhận JSON Output

Cách đơn giản nhất là hướng dẫn Claude phản hồi bằng JSON trong system prompt của bạn, và chỉ định schema chính xác bạn mong đợi:

client.messages.create(
    model="claude-opus-4-5",
    max_tokens=1024,
    system="""You are a data extraction assistant.
Always respond with a JSON object containing exactly these fields:
- name (string)
- date (string, ISO 8601 format)
- amount (number)
Respond with JSON only. No explanation.""",
    messages=[
        {"role": "user", "content": "Invoice from Acme Corp on March 5 2024 for $1,250."}
    ]
)

Mẹo để nhận JSON output đáng tin cậy:

  • Nói "Respond with JSON only" — điều này ngăn văn bản mở đầu
  • Định nghĩa schema rõ ràng, bao gồm tên trường và kiểu dữ liệu
  • Dùng "No explanation" hoặc "No markdown" để tắt code fence

Parsing và Validation

Sau khi Claude trả về JSON, phân tích và xác thực nó trong ứng dụng của bạn. Một pattern mạnh mẽ sử dụng Pydantic:

import json
from pydantic import BaseModel

class Invoice(BaseModel):
    name: str
    date: str
    amount: float

response_text = message.content[0].text

try:
    data = json.loads(response_text)
    invoice = Invoice(**data)
    print(invoice.name, invoice.amount)
except (json.JSONDecodeError, ValueError) as e:
    print(f"Parse error: {e}")
    # Thử lại hoặc xử lý khéo léo

Pydantic tự động xác thực kiểu trường và đưa ra lỗi rõ ràng nếu Claude trả về dữ liệu không mong đợi.

Key TakeawaysĐiểm chính bài học
  • Claude can return structured JSON output by instructing it via the system prompt or user message
  • Use Pydantic models or TypedDict to define the expected schema and validate Claude's response
  • Structured output is essential for pipelines where Claude's response feeds into downstream code
  • Always validate and handle parsing errors gracefully — Claude may occasionally deviate from the schema
  • Claude có thể trả về đầu ra JSON có cấu trúc bằng cách hướng dẫn qua system prompt hoặc user message
  • Sử dụng Pydantic model hoặc TypedDict để định nghĩa schema mong đợi và validate response của Claude
  • Đầu ra có cấu trúc rất cần thiết cho các pipeline mà response của Claude được đưa vào code phía sau
  • Luôn validate và xử lý lỗi parsing một cách khéo léo — Claude đôi khi có thể sai lệch so với schema
