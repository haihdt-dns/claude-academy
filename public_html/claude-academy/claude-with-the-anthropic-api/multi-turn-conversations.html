How context works in the API

Context hoạt động như thế nào trong API

Claude has no built-in memory between calls. Each API request is stateless — Claude only knows what you include in the messages array of that specific request.

To create a multi-turn conversation, you pass the entire conversation history with every request: all previous user messages and all previous assistant responses. Claude reads this history and continues the conversation from where it left off.

This design gives you full control over context — you decide exactly what Claude remembers.

Claude không có bộ nhớ tích hợp giữa các lần gọi. Mỗi API request là stateless — Claude chỉ biết những gì bạn đưa vào mảng messages của request đó.

Để tạo hội thoại nhiều lượt, bạn truyền toàn bộ lịch sử hội thoại trong mỗi request: tất cả tin nhắn user trước đó và tất cả response của assistant trước đó. Claude đọc lịch sử này và tiếp tục hội thoại từ chỗ đã dừng.

Thiết kế này cho bạn toàn quyền kiểm soát context — bạn quyết định chính xác những gì Claude nhớ.

Building the message history

Xây dựng lịch sử tin nhắn

The pattern is straightforward: after each response, append both the user message and the assistant reply to your list, then send the full list on the next call.

import anthropic

client = anthropic.Anthropic()

# Start with an empty history
messages = []

# --- Turn 1 ---
messages.append({"role": "user", "content": "My name is Alice."})

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=messages
)

# Append Claude's reply to the history
assistant_reply = response.content[0].text
messages.append({"role": "assistant", "content": assistant_reply})

# --- Turn 2 ---
messages.append({"role": "user", "content": "What is my name?"})

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=messages   # full history included
)

print(response.content[0].text)  # "Your name is Alice."

On Turn 2, the messages list contains all four messages — both user turns and the assistant reply from Turn 1. That's how Claude knows the user's name.

Pattern này rất đơn giản: sau mỗi response, thêm cả tin nhắn user và câu trả lời của assistant vào list, rồi gửi toàn bộ list trong lần gọi tiếp theo.

import anthropic

client = anthropic.Anthropic()

# Bắt đầu với lịch sử trống
messages = []

# --- Lượt 1 ---
messages.append({"role": "user", "content": "My name is Alice."})

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=messages
)

# Thêm câu trả lời của Claude vào lịch sử
assistant_reply = response.content[0].text
messages.append({"role": "assistant", "content": assistant_reply})

# --- Lượt 2 ---
messages.append({"role": "user", "content": "What is my name?"})

response = client.messages.create(
    model="claude-3-5-sonnet-20241022",
    max_tokens=1024,
    messages=messages   # toàn bộ lịch sử được đưa vào
)

print(response.content[0].text)  # "Your name is Alice."

Ở Lượt 2, list messages chứa cả bốn tin nhắn — cả hai lượt user và câu trả lời của assistant từ Lượt 1. Đó là cách Claude biết tên của user.

Context window limits

Giới hạn context window

Every Claude model has a context window — the maximum total number of tokens it can process in a single request (input + output combined). For Claude 3.5 Sonnet, this is 200,000 tokens.

As your conversation grows, the total token count grows too. For most applications this isn't a problem, but for very long sessions you have a few options:

  • Summarize old turns — replace early messages with a summary to reduce token count while preserving key information
  • Truncate the history — keep only the most recent N messages (sliding window)
  • Use prompt caching — cache the stable parts of your context to reduce cost and latency (covered later in the course)

You can check how many tokens a request will use with message.usage.input_tokens after the call, or use the token-counting endpoint before sending.

Mỗi model Claude có một context window — tổng số token tối đa nó có thể xử lý trong một request (input + output cộng lại). Với Claude 3.5 Sonnet, con số này là 200.000 token.

Khi hội thoại của bạn phát triển, tổng số token cũng tăng theo. Với hầu hết ứng dụng, điều này không phải vấn đề, nhưng với các phiên rất dài, bạn có một vài lựa chọn:

  • Tóm tắt các lượt cũ — thay thế các tin nhắn đầu bằng bản tóm tắt để giảm số token trong khi vẫn giữ thông tin quan trọng
  • Cắt bớt lịch sử — chỉ giữ N tin nhắn gần nhất (sliding window)
  • Dùng prompt caching — cache các phần ổn định trong context để giảm chi phí và độ trễ (đề cập sau trong khóa học)

Bạn có thể kiểm tra số token một request sẽ dùng qua message.usage.input_tokens sau lần gọi, hoặc dùng endpoint đếm token trước khi gửi.
