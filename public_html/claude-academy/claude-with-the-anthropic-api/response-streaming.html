Response streaming

Response streaming

Introduction

Giới thiệu

When building chat applications with Claude, there's a significant user experience challenge: responses can take 10-30 seconds to generate, leaving users staring at a loading spinner. The solution is response streaming, which lets users see text appear chunk by chunk as Claude generates it, creating a much more responsive feel.

Khi xây dựng ứng dụng chat với Claude, có một thách thức đáng kể về trải nghiệm người dùng: phản hồi có thể mất 10-30 giây để tạo ra, khiến người dùng nhìn chằm chằm vào vòng quay tải. Giải pháp là response streaming, cho phép người dùng thấy văn bản xuất hiện từng đoạn khi Claude tạo ra, tạo ra cảm giác phản hồi tốt hơn nhiều.

The Problem with Standard Requests

Vấn đề với Request thông thường

In a typical chat setup, your server sends a user message to Claude and waits for the complete response before sending anything back to the client. This creates an awkward delay where users have no feedback that anything is happening.

Trong cài đặt chat thông thường, server của bạn gửi user message đến Claude và chờ phản hồi hoàn chỉnh trước khi gửi bất cứ thứ gì trở lại cho client. Điều này tạo ra độ trễ khó chịu khi người dùng không có phản hồi nào rằng có gì đang xảy ra.

How Streaming Works

Streaming hoạt động như thế nào

With streaming enabled, Claude immediately sends back an initial response indicating it has received your request and is starting to generate text. Then you receive a series of events, each containing a small piece of the overall response.

Your server can forward these text chunks to your client application as they arrive, allowing users to see the response building up word by word. All of these events are part of a single request to Claude.

Với streaming được bật, Claude ngay lập tức gửi lại phản hồi ban đầu cho biết nó đã nhận được yêu cầu của bạn và đang bắt đầu tạo văn bản. Sau đó bạn nhận được một loạt các sự kiện, mỗi sự kiện chứa một phần nhỏ của phản hồi tổng thể.

Server của bạn có thể chuyển tiếp các đoạn văn bản này đến ứng dụng client khi chúng đến, cho phép người dùng thấy phản hồi được xây dựng từng từ một. Tất cả những sự kiện này là một phần của một request đơn đến Claude.

Stream Events

Các Stream Event

When you enable streaming, Claude sends back several types of events:

  • MessageStart — A new message is being sent
  • ContentBlockStart — Start of a new block containing text, tool use, or other content
  • ContentBlockDelta — Chunks of the actual generated text
  • ContentBlockStop — The current content block has been completed
  • MessageDelta — The current message is complete
  • MessageStop — End of information about the current message

The ContentBlockDelta events contain the actual generated text that you'll want to display to users.

Khi bạn bật streaming, Claude gửi lại một số loại sự kiện:

  • MessageStart — Một message mới đang được gửi
  • ContentBlockStart — Bắt đầu một block mới chứa văn bản, tool use hoặc nội dung khác
  • ContentBlockDelta — Các đoạn văn bản thực tế được tạo ra
  • ContentBlockStop — Content block hiện tại đã hoàn thành
  • MessageDelta — Message hiện tại đã hoàn chỉnh
  • MessageStop — Kết thúc thông tin về message hiện tại

Các sự kiện ContentBlockDelta chứa văn bản thực tế được tạo ra mà bạn sẽ muốn hiển thị cho người dùng.

Basic Implementation

Triển khai cơ bản

To enable streaming, add stream=True to your messages.create call:

messages = []
add_user_message(messages, "Write a 1 sentence description of a fake database")

stream = client.messages.create(
    model=model,
    max_tokens=1000,
    messages=messages,
    stream=True
)

for event in stream:
    print(event)

Để bật streaming, thêm stream=True vào lời gọi messages.create:

messages = []
add_user_message(messages, "Write a 1 sentence description of a fake database")

stream = client.messages.create(
    model=model,
    max_tokens=1000,
    messages=messages,
    stream=True
)

for event in stream:
    print(event)

Simplified Streaming

Streaming đơn giản hóa

Rather than manually parsing events, you can use the SDK's simplified streaming interface that extracts just the text content:

with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        print(text, end="")

This approach automatically filters out everything except the actual text content, which is usually what you need for displaying responses to users.

Thay vì phân tích sự kiện thủ công, bạn có thể sử dụng giao diện streaming đơn giản hóa của SDK chỉ trích xuất nội dung văn bản:

with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        print(text, end="")

Cách này tự động lọc ra mọi thứ ngoại trừ nội dung văn bản thực tế, đây thường là những gì bạn cần để hiển thị phản hồi cho người dùng.

Getting the Complete Message

Lấy Message hoàn chỉnh

While streaming individual chunks is great for user experience, you often need the complete message for storage or further processing. After streaming completes, you can get the assembled final message:

with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        # Send each chunk to your client
        pass
    
    # Get the complete message for database storage
    final_message = stream.get_final_message()

This gives you the best of both worlds: real-time streaming for users and a complete message object for your application logic.

Trong khi streaming từng đoạn tuyệt vời cho trải nghiệm người dùng, bạn thường cần message hoàn chỉnh để lưu trữ hoặc xử lý tiếp. Sau khi streaming hoàn tất, bạn có thể lấy message cuối cùng được ghép lại:

with client.messages.stream(
    model=model,
    max_tokens=1000,
    messages=messages
) as stream:
    for text in stream.text_stream:
        # Gửi từng đoạn đến client
        pass
    
    # Lấy message hoàn chỉnh để lưu database
    final_message = stream.get_final_message()

Điều này cho bạn điều tốt nhất của cả hai thế giới: streaming thời gian thực cho người dùng và một message object hoàn chỉnh cho logic ứng dụng của bạn.

Why Streaming Matters

By default, the Claude API waits until the entire response is generated before returning it. For short responses this is fine, but for longer outputs — detailed explanations, long-form writing, code — the user waits in silence until everything is ready.

Streaming solves this by sending tokens to your application as they are produced. The user sees text appearing word-by-word, just like typing. This makes your application feel significantly faster and more responsive, even if the total generation time is the same.

How to Stream with the SDK

The Anthropic Python SDK makes streaming straightforward. The recommended approach uses the stream() context manager:

with client.messages.stream(
    model="claude-opus-4-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a short story."}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

The text_stream property yields each text delta as a string. You can also access the final complete message after the stream ends:

    message = stream.get_final_message()
    print(message.usage)  # token counts

Raw Event Streaming

If you need lower-level control, you can iterate over the raw server-sent events:

with client.messages.stream(...) as stream:
    for event in stream:
        print(event.type)  # e.g. content_block_delta, message_stop

Each event has a type field. The most common ones are:

  • content_block_delta — carries a text chunk in event.delta.text
  • message_stop — signals the response is complete
  • message_delta — carries final usage statistics

For most applications, the text_stream helper is sufficient and much simpler to work with.

Tại sao Streaming quan trọng

Theo mặc định, Claude API chờ cho đến khi toàn bộ phản hồi được tạo ra trước khi trả về. Với các phản hồi ngắn điều này ổn, nhưng với đầu ra dài hơn — giải thích chi tiết, viết dài, code — người dùng chờ trong im lặng cho đến khi mọi thứ sẵn sàng.

Streaming giải quyết vấn đề này bằng cách gửi các token đến ứng dụng của bạn khi chúng được tạo ra. Người dùng thấy văn bản xuất hiện từng từ một, giống như gõ phím. Điều này khiến ứng dụng của bạn cảm thấy nhanh hơn đáng kể và phản hồi hơn, ngay cả khi tổng thời gian tạo giống nhau.

Cách Stream với SDK

Anthropic Python SDK làm cho streaming đơn giản. Cách tiếp cận được khuyến nghị sử dụng context manager stream():

with client.messages.stream(
    model="claude-opus-4-5",
    max_tokens=1024,
    messages=[{"role": "user", "content": "Write a short story."}]
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)

Thuộc tính text_stream trả ra từng delta văn bản dưới dạng chuỗi. Bạn cũng có thể truy cập message hoàn chỉnh cuối cùng sau khi stream kết thúc:

    message = stream.get_final_message()
    print(message.usage)  # số lượng token

Raw Event Streaming

Nếu bạn cần kiểm soát cấp thấp hơn, bạn có thể lặp qua các raw server-sent event:

with client.messages.stream(...) as stream:
    for event in stream:
        print(event.type)  # ví dụ: content_block_delta, message_stop

Mỗi event có trường type. Những loại phổ biến nhất là:

  • content_block_delta — mang một đoạn văn bản trong event.delta.text
  • message_stop — báo hiệu phản hồi hoàn tất
  • message_delta — mang thống kê sử dụng cuối cùng

Với hầu hết các ứng dụng, helper text_stream là đủ và đơn giản hơn nhiều để làm việc.

Key TakeawaysĐiểm chính bài học
  • Streaming lets you receive Claude's response token-by-token as it is generated, rather than waiting for the full response
  • Use stream=True (Python) to enable streaming; iterate over the returned event stream to process each chunk
  • Streaming dramatically improves perceived latency in chat UIs — users see output immediately instead of waiting
  • The SDK provides helper methods (stream(), text_stream) that handle the event loop for you
  • Streaming cho phép bạn nhận phản hồi của Claude từng token một khi nó được tạo ra, thay vì chờ toàn bộ phản hồi
  • Sử dụng stream=True (Python) để bật streaming; lặp qua luồng sự kiện được trả về để xử lý từng đoạn
  • Streaming cải thiện đáng kể độ trễ cảm nhận trong giao diện chat — người dùng thấy đầu ra ngay lập tức thay vì phải chờ
  • SDK cung cấp các phương thức trợ giúp (stream(), text_stream) xử lý vòng lặp sự kiện cho bạn
