Structure with XML tagsCấu trúc với XML tags

Estimated time: 10 minutes (Thời gian ước tính: 10 phút)Estimated time: 10 minutesThời gian ước tính: 10 phút

When you're building prompts that include a lot of content, Claude can sometimes struggle to understand which pieces of text belong together or what different sections are supposed to represent. XML tags provide a simple way to add structure and clarity to your prompts, especially when you're interpolating large amounts of data.

Khi bạn xây dựng các prompt bao gồm nhiều nội dung, Claude đôi khi có thể gặp khó khăn trong việc hiểu những đoạn văn bản nào thuộc về nhau hoặc các phần khác nhau được cho là đại diện cho điều gì. XML tags cung cấp một cách đơn giản để thêm cấu trúc và sự rõ ràng vào prompt của bạn, đặc biệt khi bạn đang nội suy lượng lớn dữ liệu.

Why Structure Matters

Tại sao cấu trúc quan trọng

Consider a prompt where you need to analyze 20 pages of sales records. Without clear boundaries, Claude might have trouble distinguishing between your instructions and the actual data you want analyzed.

The example above shows how unclear boundaries can make it difficult for Claude to parse your intent. By wrapping the sales records in XML tags like <sales_records> and </sales_records>, you create clear delimiters that help Claude understand the structure of your prompt.

Hãy xem xét một prompt nơi bạn cần phân tích 20 trang hồ sơ bán hàng. Không có ranh giới rõ ràng, Claude có thể gặp khó khăn trong việc phân biệt giữa hướng dẫn của bạn và dữ liệu thực tế bạn muốn phân tích.

Ví dụ trên cho thấy ranh giới không rõ ràng có thể khiến Claude khó phân tích ý định của bạn như thế nào. Bằng cách bọc hồ sơ bán hàng trong XML tags như <sales_records> và </sales_records>, bạn tạo ra các dấu phân cách rõ ràng giúp Claude hiểu cấu trúc prompt của bạn.

Custom Tag Names

Tên tag tùy chỉnh

You don't need to use official XML tags. Create descriptive names that make sense for your content:

  • <sales_records> is better than <data>
  • <athlete_information> clearly identifies user details
  • <my_code> and <docs> separate different types of content

The more specific and descriptive your tag names, the better Claude can understand the purpose of each section.

Bạn không cần sử dụng các tag XML chính thức. Tạo tên mô tả có ý nghĩa cho nội dung của bạn:

  • <sales_records> tốt hơn <data>
  • <athlete_information> xác định rõ ràng thông tin người dùng
  • <my_code> và <docs> phân tách các loại nội dung khác nhau

Tên tag của bạn càng cụ thể và mô tả, Claude càng có thể hiểu mục đích của từng phần tốt hơn.

When to Use XML Tags

Khi nào dùng XML Tags

XML tags are most useful when:

  • Including large amounts of context or data
  • Mixing different types of content (code, documentation, data)
  • You want to be extra clear about content boundaries
  • Working with complex prompts that interpolate multiple variables

Even for shorter content, XML tags can help serve as delimiters that make your prompt structure more obvious to Claude.

XML tags hữu ích nhất khi:

  • Bao gồm lượng lớn context hoặc dữ liệu
  • Kết hợp các loại nội dung khác nhau (code, tài liệu, dữ liệu)
  • Bạn muốn làm rõ hơn về ranh giới nội dung
  • Làm việc với các prompt phức tạp nội suy nhiều biến

Ngay cả với nội dung ngắn hơn, XML tags có thể giúp làm dấu phân cách khiến cấu trúc prompt của bạn rõ ràng hơn với Claude.

Real-World Application

Ứng dụng thực tế

In practice, you might structure a prompt like this:

<athlete_information>
- Height: 6'2"
- Weight: 180 lbs
- Goal: Build muscle
- Dietary restrictions: Vegetarian
</athlete_information>

Generate a meal plan based on the athlete information above.

This makes it crystal clear that the height, weight, goal, and restrictions are all related athlete data that should be considered together when generating the meal plan.

While you might not see dramatic improvements with simple prompts, XML tags become increasingly valuable as your prompts grow more complex and include larger amounts of varied content.

Trong thực tế, bạn có thể cấu trúc một prompt như thế này:

<athlete_information>
- Height: 6'2"
- Weight: 180 lbs
- Goal: Build muscle
- Dietary restrictions: Vegetarian
</athlete_information>

Generate a meal plan based on the athlete information above.

Điều này làm rõ hoàn toàn rằng chiều cao, cân nặng, mục tiêu và hạn chế ăn uống đều là dữ liệu vận động viên liên quan cần được xem xét cùng nhau khi tạo kế hoạch bữa ăn.

Mặc dù bạn có thể không thấy sự cải thiện đáng kể với các prompt đơn giản, XML tags trở nên ngày càng có giá trị khi prompt của bạn phức tạp hơn và bao gồm lượng nội dung đa dạng lớn hơn.

XML Tags vs Other Delimiters

You may have seen other delimiters used in prompts — triple backticks (` ``` `), triple dashes (---), or angle brackets. XML tags are generally preferred with Claude because:

  • They're self-documenting — the tag name tells you what the content is
  • They support nesting — you can put <example> inside <examples>
  • Claude's training includes a lot of XML, so it parses tags reliably
  • They work for both input structure (your prompt) and output structure (asking Claude to respond in XML)

Using XML Tags for Output Structure

XML tags aren't just for structuring your input — you can also ask Claude to respond using tags, making the output easier to parse programmatically:

Analyze this product review and respond using these tags:
<sentiment>positive | negative | neutral</sentiment>
<key_issues>bullet list of issues mentioned</key_issues>
<recommended_action>one sentence</recommended_action>

<review>
{review_text}
</review>

Claude will structure its response accordingly, and you can extract each field with a simple regex or XML parser.

Nesting Tags for Complex Prompts

For prompts that include multiple examples or datasets, nesting helps Claude distinguish between them:

<examples>
  <example>
    <input>What is the capital of France?</input>
    <output>Paris</output>
  </example>
  <example>
    <input>What is the capital of Japan?</input>
    <output>Tokyo</output>
  </example>
</examples>

Now answer: What is the capital of Brazil?

Tag Naming Conventions

Good tag names are lowercase, use underscores for spaces, and describe the content role — not just the content type:

  • <user_query> instead of <text>
  • <reference_document> instead of <document>
  • <previous_attempts> instead of <history>
  • <grading_criteria> instead of <criteria>

XML Tags so với các dấu phân cách khác

Bạn có thể đã thấy các dấu phân cách khác được dùng trong prompt — triple backticks (` ``` `), triple dashes (---), hoặc dấu ngoặc nhọn. XML tags thường được ưu tiên với Claude vì:

  • Chúng tự ghi lại tài liệu — tên tag cho biết nội dung là gì
  • Chúng hỗ trợ lồng nhau — bạn có thể đặt <example> trong <examples>
  • Training của Claude bao gồm nhiều XML, vì vậy nó phân tích tag một cách đáng tin cậy
  • Chúng hoạt động cho cả cấu trúc đầu vào (prompt của bạn) và cấu trúc đầu ra (yêu cầu Claude phản hồi bằng XML)

Dùng XML Tags cho cấu trúc đầu ra

XML tags không chỉ để cấu trúc đầu vào của bạn — bạn cũng có thể yêu cầu Claude phản hồi bằng tags, làm cho đầu ra dễ phân tích lập trình hơn:

Analyze this product review and respond using these tags:
<sentiment>positive | negative | neutral</sentiment>
<key_issues>bullet list of issues mentioned</key_issues>
<recommended_action>one sentence</recommended_action>

<review>
{review_text}
</review>

Claude sẽ cấu trúc phản hồi của nó theo đó, và bạn có thể trích xuất từng trường bằng regex đơn giản hoặc XML parser.

Với các prompt bao gồm nhiều ví dụ hoặc dataset, việc lồng nhau giúp Claude phân biệt giữa chúng:

<examples>
  <example>
    <input>What is the capital of France?</input>
    <output>Paris</output>
  </example>
  <example>
    <input>What is the capital of Japan?</input>
    <output>Tokyo</output>
  </example>

Now answer: What is the capital of Brazil?

Quy ước đặt tên Tag

Tên tag tốt là chữ thường, dùng dấu gạch dưới cho khoảng trắng và mô tả vai trò nội dung — không chỉ loại nội dung:

  • <user_query> thay vì <text>
  • <reference_document> thay vì <document>
  • <previous_attempts> thay vì <history>
  • <grading_criteria> thay vì <criteria>

  • XML tags tạo ranh giới rõ ràng trong các prompt chứa lượng dữ liệu lớn hoặc nhiều loại nội dung khác nhau
